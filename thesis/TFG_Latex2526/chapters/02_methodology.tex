\section{System Overview and Core Automated Workflow}
\label{sec:methodology-overview}

This section formalizes the modular Python pipeline introduced in \Cref{sec:scope}, translating the clinical decision-support framework into an executable computational workflow. For each patient identifier, a pre-segmented coronary lumen mask is processed sequentially into quantitative stenosis metrics, a CAD-RADS~2.0-oriented report, and an interactive visualization session.

The workflow comprises four automated blocks (\crefrange{sec:methodology-block1}{sec:methodology-block4}) executed as a linear chain, with each stage consuming the artifacts produced by its predecessor and no manual intervention between steps. A unified patient identifier routes ASOCA, MACS-18, and synthetic cohorts through the same implementations, while runtimes and extraction metrics are logged for \Cref{sec:methodology-validation}.

\section{ASOCA and MACS-18: Coronary Segmentation and Labeling Data}
\label{sec:methodology-datasets}

In medical image analysis, \emph{segmentation} denotes the partition of a three-dimensional scan into meaningful regions. For each voxel in the volume, an expert or algorithm decides whether it belongs to a structure of interest, such as the blood-filled interior (\emph{lumen}) of the coronary arteries, rather than to background tissue, myocardium, or surrounding anatomy. The result is not a single measurement but a spatial map that localizes the vessel tree within the patient-specific CCTA grid.

The ASOCA and MACS-18 resources provide this map, together with companion anatomical label volumes, for a shared cohort of 40 CCTA cases (20 normal and 20 diseased anatomy). These data served primarily as the reference on which Blocks~1--4 were designed and implemented. Once the pipeline was in place, the full cohort was processed to evaluate end-to-end behavior. The experimental protocol and result analysis are reported in \Cref{sec:methodology-validation}.

\subsection{Segmentation and Label Volumes}
\label{subsec:dataset-formats}

For each patient case, the \emph{segmentation annotation} is stored as a three-dimensional voxel grid in NRRD format. Each voxel indicates whether it belongs to the coronary lumen. The pipeline treats this volume as a binary mask from which centerlines, branch topology, and surface geometry are extracted (Block~1). The grid is registered to the same physical coordinate system as the source CCTA, preserving patient-specific scale and orientation.

The \emph{segment label volume} is a separate three-dimensional grid aligned with the segmentation, stored as a compressed NIfTI file. Instead of a binary lumen flag, each foreground voxel stores an integer class identifier that maps to a standardized coronary segment under the AHA 17-segment model~\cite{austen1975} (e.g., proximal left anterior descending, circumflex branches). Background voxels are assigned zero. The same label volumes are used for every case in the cohort regardless of whether the ASOCA or MACS-18 lumen mask is supplied to Block~1.

\subsection{ASOCA Dataset}
\label{subsec:dataset-asoca}

The ASOCA (\emph{Automated Segmentation of Coronary Arteries}) challenge established the first large, standardized benchmark for fully automatic segmentation of complete normal and diseased coronary trees from CCTA~\cite{gharleghi2022asoca}. The resource addresses the difficulty of imaging small, moving vessels and supports research on end-to-end coronary analysis beyond semi-automatic, expert-guided workflows.

ASOCA is a publicly available dataset. In this project, its release provided the initial lumen segmentation masks for the 40-patient cohort and constituted the working ground truth during pipeline development. These challenge annotations define the coronary tree extent used as the default Block~1 input and remain the public reference against which the hospital-refined alternative described below is compared.

\subsection{MACS-18 Dataset}
\label{subsec:dataset-macs}

While public benchmarks such as ASOCA have accelerated algorithm development, their lumen annotations often prioritize voxel-level overlap over topological completeness~\cite{acebes_macs18_wip}. Discontinuities in the mask and inconsistent distal coverage can limit centerline extraction, branch-level quantification, and geometric analysis in Blocks~1 and~2.

MACS-18 (\emph{Multiclass Anatomical Coronary Segmentation, 18-segment}) is a re-segmentation of the same 40 ASOCA patient volumes currently under development at Hospital de la Santa Creu i Sant Pau under the supervision of C\'{e}sar Acebes Pinilla~\cite{acebes_macs18_wip,acebes2024}. Unlike ASOCA, this resource is not yet publicly released. Expert refinements target continuous lumen connectivity from the aortic root to the most distal visible branches, yielding more anatomically faithful masks without altering the underlying imaging data or patient identity. The aim is to obtain more accurate segmentations of the existing cases, not to introduce new patients or a different labeling scheme. Each MACS-18 volume therefore uses the identical AHA segment label map as its ASOCA counterpart; only the lumen mask differs between the two sources. Both datasets are processed by the same pipeline implementation.
